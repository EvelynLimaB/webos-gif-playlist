# Security policy

## Supported versions

Only the newest pre-release branch receives security fixes. No build is considered production-stable until its documented physical-TV checklist passes.

## Reporting a vulnerability

Do not publish vulnerabilities that could expose root access, allow command injection, damage system files, or make a TV unbootable. Report them privately through GitHub's security-advisory feature for this repository. Include the affected commit, TV/firmware, reproduction steps, impact, and a safe recovery procedure.

## Trust boundary

This application requires a rooted TV and invokes the Homebrew Channel root execution service. Anyone who can operate the app or authenticate as root over SSH already has privileged access to the device.

The project still treats all imported media and UI input as untrusted:

- URLs are base64 transported, scheme/length/control-character checked, and downloaded to temporary files.
- File format is detected from bytes rather than names.
- Logical dimensions and storage limits are checked before import.
- Playlist identifiers use a restricted character set.
- Local upload paths on the TV are generated by the helper rather than derived from local filenames.
- Mutating manager operations are serialized by an atomic lock.
- The manager refuses foreign screensaver mounts and only unmounts an override it can identify as its own.

## Operational safety

- Keep Telnet disabled after SSH key authentication is configured.
- Run Compatibility check before activation after every firmware or Homebrew change.
- Use **Apply temporarily** before **Enable at boot**.
- Keep the recovery commands from the README available from another device.
- Never install a package from an untrusted source merely because its app ID matches this project.
